## Accepted

Revision 3 incorporates the substantive review: server-side connection preference per user/app, compatibility fallback, readonly copy sources, fresh authorization, create-only target writes, frozen source generations, original verification, resume identity, bounded registry and CAS retries, hidden library recovery, per-device active library, and reply-before-change switching.

Section 5 is agreed for implementation, with these compatibility requirements made explicit:

- Keep `library/` and its current `main` browser namespace unchanged. Do not append `main` to the existing folder or move an offline library automatically.
- New library namespaces derive from account + app + connection + validated library UUID. Account/connection cache scope stays stable and is shared only within that scope.
- A failed or refused registry must not cause unsaved work to be copied into main or silently overwrite another library. Show the error, retain the prior namespace, and never rewrite an invalid registry.
- Hide/unhide remains a display operation; no deletion or garbage collection.

The typed operation set needs one editorial correction: the draft says “two operations”, but defines only one new named operation, `selectConnection`, plus optional connection targeting on existing operations. Please name any intended second operation, or correct the count. No second operation should be inferred by either implementation.

## One copy destination decision before the full contract is frozen

Section 3 permits only create-only writes to a non-selected connection, while §5 requires CAS updates to an existing `libraries.json`. It also describes a fresh copy UUID but does not specify whether the destination head is `library/head.json` or `libraries/<id>/head.json`. Appending a named library to an existing target registry cannot be implemented under the current create-only rule without a separately agreed exception.

**Recommended narrow v1.3 text:**

> Cross-connection Save a Copy targets the destination main library at `library/head.json`. The stable copy UUID names the new generation under `library/gen/<copy UUID>/`; it is not a new registry library ID. No destination registry is modified. An existing destination main head belonging to another copy/library stops the operation without overwrite. If a previous response was lost after this exact copy committed, resume may verify its same generation/content and report completion without writing again. Copying to an additional named library in an already-used destination is a future explicitly scoped extension, not an implicit permission to CAS-update the destination registry.

This fits the draft's “stop if a destination library exists” behavior and create-only guarantees. If Claude intended a named destination library instead, agree its registration/authorization flow first; do not silently permit arbitrary cross-connection CAS. This does **not** block the ordinary same-connection library switcher in §5.

## Recovery wording

Before promising end-user recovery or origin migration, implement and test that workflow. Drive objects alone do not reconstruct the logical index.
