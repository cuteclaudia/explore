# Outdoor data for Explore: source assessment and integration plan

28 October 2026, Australia/Sydney. Scope: ski pistes/lifts, mountain biking, hiking, climbing routes, terrain, route planning and authoritative access information for a public site that may later offer paid features.

## What was actually checked

Ordinary web requests to search engines and provider websites were blocked by the execution environment (HTTP CONNECT 403), including after network permission was granted and a separate network attempt. Direct access also failed DNS. No claim is made that current public websites, live feeds, prices or commercial API contracts were fully checked.

Official project repositories were accessible over Git, and their source documentation was read. This provides primary evidence for the findings below. Repository snapshots are evidence of their published documentation, not a live endpoint test or a guarantee that hosted-site terms have not changed. Sources that could not be checked are marked as candidates, never approved integrations. No emails or provider applications were sent.

## Recommended combination

1. **OpenStreetMap data as the shared geometry foundation.** Already queried by Explore via Overpass for small areas, with request limits and caching. Extract raw features rather than copying commercial maps. At subscription scale use regional extracts, a tile pipeline or a contracted provider instead of depending on donated query capacity.
2. **OpenSnowMap for specialist ski presentation/reference**, or its published OSM ski extracts in a hosted pipeline. Do not silently hotlink its relief/basemap layers. A pistes-only overlay has explicit published conditions; reconfirm live terms before adding it.
3. **Waymarked Trails for marked hiking/MTB/winter route discovery**, external references and a moderate overlay under the terms published in its source documentation; live-site policy still needs rechecking. Do not mass-download their convenient GPX files into our catalogue.
4. **OpenBeta for climbing areas and individual climbs**, as a separately licensed data adapter with a bounded, opt-in public API lookup. Its published FAQ says climbing data excluding photos/code is CC0. Confirm regional coverage and endpoint limits with a small pilot. OSM climbing-site pins alone are not pitch diagrams.
5. **Park, land-manager and resort sources for access/closures.** Keep authority, timestamp and licence attached to every imported record. A trail in OSM is not an operational status feed.
6. **A separate routing engine for route creation.** Openrouteservice or BRouter can help with hiking/cycling; neither should be presented as an automatic safe climbing or ski-tour route planner.

## Specific feature handling

### Skiing

Use `piste:type`, `piste:difficulty`, `aerialway`, route relations, names/references and available grooming/oneway tags. Separate downhill, Nordic and ski touring rather than colouring them as interchangeable activities. Preserve original source grades; regional symbols/colours differ. Lift geometry is not proof a lift runs today. Resort PDF art remains copyrighted independently of underlying geographic facts. Ski touring adds avalanche/seasonal constraints not covered by terrain shading; live operational/avalanche information needs an authority/licensed source. No automatic safe-route claim.

### MTB and hiking

Keep `mtb:scale`, `mtb:scale:uphill`, `sac_scale`, `surface`, `smoothness`, incline and access restrictions as separate attributes when present. Missing tags mean unknown, not easy/permitted. OSM route relations can have missing, unordered or clipped member geometry; current small-area results must not be advertised as complete routes. Only compute full-route metrics after retrieving and validating a complete ordered path. GPX elevation/ascent remains approximate. Hiking paths and marked named routes are different discovery concepts.

### Climbing

Separate climbing **sites/areas** from individual climbs, pitches, approaches and topographic diagrams. A 2D line at a cliff is not a reliable depiction of a vertical route. Preserve the grading system (French, UIAA, YDS, Ewbank, V-scale etc.) instead of guessing equivalences. OpenBeta is the preferred detailed-data candidate. Check Australian coverage and access/sensitive-site policy before import. Never copy theCrag/Mountain Project descriptions or photo topos without permission. Per-photo licence decisions are mandatory even when the associated climb data is CC0.

## Proposed data contract for future adapters

Every record: provider + stable source ID + source URL + dataset licence/version + attribution + retrieved timestamp + activity + geometry completeness + grade/system + access state/source/time. Optional fields remain explicitly unknown. Store separately licensed providers independently rather than erasing provenance in one merged database. Apply deduplication by geometry/source IDs cautiously; never merge conflicting access claims into an authoritative answer.

External adapters must validate numeric geometry, coordinate/count/byte bounds and text lengths; use textContent, fixed/validated external link origins, bounded concurrency, caching, timeout/cancellation and provider Retry-After. Avoid arbitrarily proxying URLs from users or third-party tags. Media must pass its own licence/type/size rules.

Keep route viewing distinct from creation, saved account plans distinct from GPX browser previews, and base tiles distinct from the underlying dataset. Save/share account features need their own authorization and privacy model; none is implemented by adding a map layer. No community publishing is enabled by this work.

## Implementation delivered with this review

The existing `/places` planner now has a compact heading, one place search, visible activity filters, Map/List switching, a bounded first-50 feature list, original mapped grades/access plus OSM source links, expandable GPX/trip tools and correctly styled dynamic layer labels. Activity chips synchronize with the detailed layer controls and account preference loading. The list displays empty/zoom/loading/error states and has a manual refresh. `/explore` redirects to the actual map instead of promising a future map.

Clickable details still use the existing bounded Overpass adapter. Hiking/MTB Waymarked Trails and OpenSnowMap pistes-only reference raster overlays have also been added under the terms in the reviewed primary-source snapshots, with attribution, valid origin referrer and tile prefetch disabled. They show trails independently of the details API; they do not populate the list or establish live opening status. Tile/provider failures have their own visible status. An optional MapTiler satellite layer is prepared but remains disabled until a domain-restricted browser key and a suitable no-spend plan are configured; see `SATELLITE-SETUP.md`. A bounded opt-in OpenBeta route lookup is now integrated from its documented public GraphQL schema, with no photos/descriptions and separate source status; no paid service or routing engine has been enabled; live endpoint reachability and Thredbo coverage cannot be independently certified from this environment. No availability guarantee is inferred from saving preferences. Climbing is explicitly labelled as sites. GPX previews remain in-browser, not uploaded.

Outstanding work: verified provider coverage/live requests, account-scoped saved places/plans, owner-editable curated collections and story associations, complete-route retrieval, export/share authorization, licensed specialist overlays and a routing pilot. These require subsequent implementation and testing; they're not represented by decorative controls.

## Pilot and acceptance plan

- Australia: Canberra/Brindabellas hiking, Stromlo MTB, Thredbo/Perisher pistes and Blue Mountains climbing. These are test targets, not asserted coverage passes.
- Overseas: a well-mapped Alpine resort and a US climbing crag; test multilingual names and different grade scales.
- Compare a sample with the original source and current authority access/closure pages. Record missing geometry, names, grades and stale records.
- Exercise no-data areas, too-wide views, provider timeout/429/partial Overpass responses, geometry caps and source attribution.
- Test phone/tablet layout, Map/List switching, keyboard use, map fallback, activity/preference synchronization and private GPX import/clear.
- Before adding another specialist feed or scaling these reference overlays, archive its exact current terms, agree volumes/keys/costs, check embedding/privacy headers and measure requests/cache hit rate. Confirm availability on a physical user's browser; local fixture tests do not establish internet/provider health.

## Individual rock, ice and mixed climbing routes

User explicitly requested individual climbing and ice routes during implementation. The verified OpenBeta schema has `ice`, `mixed` and `snow` disciplines and Water Ice (`wi`) grades alongside rock scales. The implementation uses a bounded `cragsWithin` lookup followed by one batched request for at most eight canonical crag IDs and at most 300 returned route points. Both responses pass the existing 3 MiB streaming guard; results are cached and provider requests spaced. `Rock climbing` and `Ice climbing` controls are separate from `Climbing sites`.

Only names, original grades, disciplines, length where known, source IDs and coordinates are used. No photos, route-description text, topos, user accounts or paid API are copied/connected. A climb's own coordinate is distinguished from a fallback area location. These are route records/points, not manufactured vertical route lines. No result means no records in the bounded query, not that no climbs exist or ice is safe/formed. Live endpoint/schema compatibility still needs a user check because ordinary internet requests are blocked here.
