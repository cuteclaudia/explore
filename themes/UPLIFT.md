# Theme uplift

The 50 stock themes are being redesigned five at a time to the standard of **Explore by Claudia**
(the reference theme, `explore`). Each uplifted theme keeps its id and gains a `design/` folder:

```
themes/<id>/design/
  DESIGN.md        the specification: header, hero, navigation, sections, crops, type, colour,
                   widgets, phone behaviour, empty site, and what the importer must add
  content.html     design reference with sample content (open in a browser; resize for phone)
  empty.html       the same theme for a brand-new tenant, as the Website Manager shows it
  screens/         desktop (1440 px) and phone (390 px) captures of both references
  images/          stock photographs for the theme, credited in CREDITS.md
```

Design references are **not** starter content. A new tenant starts with empty pages: `empty.html`
shows the guided placeholders the owner sees in Website Manager, and none of them is published.
Sample text and photographs stay in the references only.

Generated by `_tools/design-references.mjs` (with credits from `_tools/design-credits.mjs`);
`npm run test:themes` checks the references are current, script-free, offline and fully credited.

### Review checklist (each theme, desktop and phone)

1. Matches `content.html` / `screens/` at 1440 px and 390 px: type sizes, spacing, crops, colours.
2. A new tenant sees `empty.html`: guided placeholders in Website Manager, and **no** placeholder,
   sample text or stock photo on the published site (empty sections are left out).
3. Choosing a stock photo for a slot works; removing it leaves a clean section, not a broken frame.
4. Light and dark both readable; forced-colours mode falls back to system colours.
5. Widgets switch on and off and sit where the spec says.
6. Keyboard, focus and screen-reader labels work; nothing loads from outside SoraSpace.

## Explore benchmark

What "Explore quality" means, measured from `src/templates/explore.html`:

| Aspect | Explore | Applied to every uplifted theme |
| --- | --- | --- |
| Body text | 16 px, line height 1.6 | Same. Never smaller than 15 px for reading text, 12 px for labels |
| Display heading | clamp(46 px, 6 vw, 78 px), weight 400, line height 1.1 | Each theme sets its own face and weight, same fluid range (up to about 88 px) |
| Section heading | 42 px (34 px on phones) | 30–52 px desktop, 28–40 px phone |
| Eyebrow labels | 12 px, letter-spacing 3 px, capitals | 12 px, 0.16–0.18 em, capitals |
| Width and margins | max 1300 px, side padding 5 % | 1180–1400 px per theme, side padding 5 % (4 % for full-bleed photo themes) |
| Section rhythm | 50 px top and bottom (35 px phone) | 72 px desktop, 48 px phone |
| Hero | full-bleed photo, 610 px (540 phone), dark gradient from the text side | Photo heroes keep a gradient on the text side only, sized to the photograph |
| Cards | radius 10 px, image 250 px tall, body padding 24 px | Per-theme radius; image crop by ratio (below), body padding 20–24 px |
| Grid | 3 columns, gap 24 px, one column under 750 px | 3–4 columns desktop, 1–2 on phones |
| Feature panel | panel over the hero with featured item, latest and quick links | Same widget, placed per theme |

## Settings the current importer already supports

`theme.json` schemaVersion 1. These are all changed directly in the uplifted themes (the
`theme.json` files are regenerated, ids and paths unchanged):

- `baseTemplate`, `purpose`, `pages`, `pageLabels`, `density`, `recommendedVisibility`
- `colours.light` / `colours.dark` (all 11 tokens, WCAG AA checked)
- `typography` (heading and body stacks, weight, case, tracking, scale)
- `shape` (radius, button radius), `layout.maxWidth`
- `layout.header` (`split`, `centered`, `minimal`, `bar`) and `layout.hero` (`full-bleed`,
  `split`, `banner`, `statement`, `text`)
- `layout.home`: ordered sections `intro`, `cards` (`columns`, `count`, `images`), `list`,
  `feature`, `gallery` (`even`, `masonry`, `wide`, `strip`), `facts`, `people`, `cta`, `contact`
- `widgets.enabled` / `widgets.suggested` from `widgets.json`

ChatGPT's import note mentions a simpler palette-and-layout importer. Anything above that it does
not read yet is a gap to close first, before the new features below.

## New layout features SoraWebSite needs

Shared across batches. F1–F18 came with batch A, F19–F26 with B, F27–F40 with C. Each theme's `DESIGN.md` says which it uses and with what values. Proposed
settings live in the spec, not in `theme.json`, until the importer supports them; they would then
be added as new optional fields (schemaVersion stays 1).

| ID | Feature | What it needs |
| --- | --- | --- |
| F1 | **Photo hero** | Hero image per site with focal point (x, y %) and zoom (100–150 %), overlay side (`left`, `bottom`, `none`) and strength, optional caption. Separate focal point for phones. |
| F2 | **Theme stock photos** | Each theme ships its own small set (`design/images/`, credited). In Website Manager, an image slot offers "Use a photo from this theme" beside Upload. Stock photos are **never** placed automatically on a new site. Show credits on the site's credits line while one is in use. Keep sets per theme, not a browsable library (Pexels licence). Photos that would misrepresent the tenant (their own artwork or portfolio, their team, jobs they completed) are **reference only** and never offered; each DESIGN.md lists which photos can be offered. |
| F3 | **Image slots with crops** | Every image in a section has a crop ratio (`21:9`, `16:9`, `3:2`, `4:3`, `5:4`, `4:5`, `3:4`, `2:3`, `1:1`, `natural`) and the owner's focal point. Phones may use a different ratio (given per slot). |
| F4 | **Overlay header** | Header drawn over a full-bleed hero in hero text colour, solid on every other page and when there is no hero image. |
| F5 | **Utility bar** | Thin bar above the header: dateline and issue, or licence, phone and hours. Each item optional. |
| F6 | **Lead story grid** | Lead story (8/12) with image, kicker, headline, standfirst, byline, beside a rail of two stories and an "In brief" list (4/12). |
| F7 | **Full-width image band** | Single photograph across the page (21:9 desktop, 4:5 phone) with kicker, title and credit over a bottom gradient. |
| F8 | **Split feature with pull quote** | Image (4:5 or 4:3) beside a large quote, title, summary and link. Image side selectable. |
| F9 | **Artwork details** | Gallery items with title, medium, size, year and availability (`available`, `sold`, `not for sale`, none), shown under a mat. Series list: cover, title, years, count. |
| F10 | **Steps** | Numbered steps (2–5), each a title and one sentence. |
| F11 | **Phone action bar** | On phones, a bar fixed to the bottom with up to two actions (call, quote, book). Business themes only. |
| F12 | **Guided empty site** | Website Manager draws every enabled section with dashed, labelled placeholders showing the crop and what goes there. Published pages leave empty sections out and never show placeholders, sample text or stock photos. |
| F13 | **Masthead header** | Large centred title with optional tagline, rules above and below the navigation, sections scroll sideways on phones. |
| F14 | **Trip details** | Journal entries can carry days, distance and season, shown as chips on the feature and cards. |
| F15 | **Default appearance** | A theme can start in dark (photography) while still offering System and Light. |
| F16 | **Phone menu** | Header collapses to name + Menu below 760 px; menu opens as a full-width sheet; sections nav may scroll sideways instead (F13). |
| F17 | **Credits line** | Footer line listing photographers while stock photos are in use, removed automatically when none are. |
| F18 | **Mixed-width photo strip** | `strip` gallery with set relative widths (e.g. 1.4 / 1 / 1.2 / 1 / 1.3), fixed height, five photos; two on phones. |
| F19 | **Menu with prices** (batch B) | List rows with a dotted leader to a right-aligned price, grouped by menu section tabs (Breakfast, Lunch…) that scroll sideways on phones. Optional dietary note. |
| F20 | **Facts card over the hero** (B) | The `facts` section drawn as a white card overlapping the bottom of the hero (3 or 4 items; stacks on phones). Restaurant: open / find us / call. Stay: sleeps / bedrooms / from / minimum, plus the booking button. |
| F21 | **Opening hours table** (B) | Day-by-day hours with today highlighted, beside an optional click-to-load map. |
| F22 | **Numbered services list** (B) | Typographic grid of services (01–06), three columns with dividing rules, no images. |
| F23 | **Typeset book cover** (B) | When a writer has no cover image, SoraSpace sets the title and name in the theme's type on a colour block (`art1`). An uploaded cover replaces it. |
| F24 | **Round portraits** (B) | `people` cards with circular 1:1 portraits, name, role in accent, one line. |
| F25 | **Photo mosaic** (B) | `gallery` with one large photo (2 rows) and four smaller ones, captions as chips; phones show three. |
| F26 | **Image-backed call to action** (B) | `cta` band over a dimmed photo. |
| F27 | **Case study with a result** (C) | `cards` item with sector, title, one line and a result figure (accent, 26–34 px) plus a short label. Leave the figure out when empty. |
| F28 | **Availability chip** (C) | Short status in the hero with a dot ("Taking new projects from February"). Manager shows when it was last edited; empty means no chip. |
| F29 | **Offer sticker** (C) | A small tilted card over the hero photo (`art2`), two lines. Optional; never a health or price claim the owner hasn't written. |
| F30 | **Gig list with ticket status** (C) | Dated rows: date block, venue, town · details, status (on sale, few left, sold out, free, cancelled), outbound ticket link. Past gigs drop off at publish. |
